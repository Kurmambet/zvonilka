# Signaling: WS-вход, поставка 2

Реализован короткий проверочный путь:
`WS → authenticate → AuthService → Redis join → joined → disconnect/leave`.

Это не готовый signaling для звонка: нет heartbeat, обновления JWT,
событий участников, отключения заменённого окна и пересылки offer/answer/ICE.
До следующей поставки соединение намеренно ограничено короткой сессией.

## Протокол

Endpoint: `/api/v1/rooms/{room_id}/ws`.
Схемы поставки 1 остаются без изменений. Приглашение заранее погашается через REST.
После HTTP Upgrade клиент отправляет:

```json
{
  "version": 1,
  "type": "authenticate",
  "request_id": "00000000-0000-4000-8000-000000000001",
  "room_id": "00000000-0000-4000-8000-000000000002",
  "access_token": "<access JWT>",
  "app_version": "0.5.0-dev.1",
  "capabilities": []
}
```

Room ID в URL и сообщении должен совпадать. Query string целиком запрещён,
в том числе для передачи токена. Некорректный UUID пути, query string и превышение
локального лимита подключений отклоняются до accept: через Uvicorn это отказ
HTTP Upgrade, обычно HTTP 403, а не JSON error и не WS close code для клиента.

После accept:

- Только текстовые сообщения; binary отклоняется с error и закрытием 1003.
- Первое сообщение должно соответствовать Authenticate, версия — целое 1.
- Если schema-valid сообщение содержит другую комнату, error коррелируется его
  request_id. Для malformed/непрошедшего схему сообщения request_id равен null.
- Авторизация вызывает существующий `AuthService.authenticate()`, включая БД-сессию.
- Пользователь берётся из Principal; поколение генерирует сервер.
- Снимок берётся из `result["room"]` существующего Lua join, не отдельным snapshot.
- Ответ joined подтверждает только этот вход, не WebRTC/медиа.
- Capabilities пока согласуются в пустой список.
- Любое следующее прикладное сообщение в этой поставке отклоняется:
  heartbeat/offer/answer/ICE пока не реализованы.

Бюджет сессии до начала закрытия: `min(20 секунд, presence_ttl / 2)`, отсчёт начинается перед join.
Ожидание join вычитается из этого бюджета. Если бюджет уже исчерпан, joined
не отправляется. По истечении оставшегося срока сервер закрывает WS кодом 1000
и пытается выполнить leave. Закрытие и cleanup имеют отдельные ограниченные таймауты,
поэтому это не обещание точного wall-clock времени освобождения presence.
Это явное промежуточное ограничение, не reconnect
и не стратегия длительного звонка. Клиент не должен автоматически создавать
бесконечный цикл повторных входов.

## Ограничения и зависимости

Значения Policy по умолчанию:

| Ограничение | Значение |
| --- | --- |
| Ожидание первого сообщения после accept | 5 секунд |
| Авторизация + join вместе | 5 секунд |
| Одна отправка/закрытие | до 2 секунд |
| Попытка leave | до 3 секунд |
| Локальный максимум обслуживаемых сокетов, включая неавторизованные | 32 |
| Прикладное сообщение | 16384 UTF-8 байта |

Это не per-IP rate limiter и не защита от volumetric DoS. До публичного
развёртывания нужны ограничения на proxy/сервере и следующие поставки.
Локальный счётчик и зависимости живут в одном event loop, один API worker.
Несколько workers/reload не являются поддерживаемым режимом продукта.

В server.py явно выбирается `ws="websockets"`, входной лимит 16384 байта,
очередь WS backend 4 и выключенное per-message compression. Это лимиты
выбранного backend; прикладная проверка выполняется уже после сборки сообщения.
На сетевом превышении размера backend может закрыть WS кодом 1009 БЕЗ JSON error.
Собственный запуск Uvicorn должен сохранять те же параметры. Это не ограничитель
всех HTTP-соединений или общего расхода памяти процесса.

Новая runtime-зависимость: `websockets>=13,<16`. Она нужна Uvicorn для реального
HTTP Upgrade/frames, а также для loopback TCP-тестов. Базовый `uvicorn` сам по себе
не гарантирует установленного WS backend. Диапазон ограничен явно, без обновления
всего стека. Установка и согласованное обновление pyproject/uv.lock — через uv add
из корня проекта, не ручное редактирование lock. В среде автора эти версии вместе
с проектом не установлены и совместимость ещё должна пройти приложенные тесты.

## Cleanup и ошибки

Флаг join_attempted ставится ДО ожидания Redis EVAL. Даже при потерянном ответе
или отмене join обработчик делает ограниченную попытку leave с теми же
user_id/room_id/generation. Поздний cleanup не использует поколение нового входа.
`stale_generation`, `room_closed`, `room_not_found` при cleanup ожидаемы и не
превращаются в исключение обработчика.

При отмене обработчика cleanup защищён от AnyIO cancel scope и ограничен по
времени; CancelledError не проглатывается. Отдельных долгоживущих задач не создаётся.
Жёсткое завершение процесса, повторная отмена, недоступный Redis или неопределённый
порядок сетевых команд всё ещё могут оставить presence до lease expiry.
Это best effort, а не гарантия мгновенного rollback Redis.

Отказ Redis/БД, timeout операции и schema mismatch не возвращают joined.
Schema mismatch отображается в dependency_unavailable без перезаписи агрегата.
Неизвестный RoomError — internal_error, а не произвольный текст из Redis.
Исключения и входные сообщения не сериализуются в логи/ответы.

Замена поколения уже происходит в Redis. Эта поставка не уведомляет старый
сокет о замене и не реализует проверку поколения перед дальнейшей пересылкой,
поскольку пересылки пока нет. Инвариант позднего leave сохраняет репозиторий.
REST close пока не рассылается в WS: это отдельно от реализации входа.

## Уровни проверки

- test_signaling_service.py: unit-тесты сервиса; auth/rooms — doubles.
- test_signaling_transport.py: настоящий FastAPI router и ASGI WS-события,
  включая существующий SafeHttpBoundary; auth/rooms — doubles, без TCP.
- test_signaling_network.py: настоящий loopback TCP, Uvicorn, HTTP Upgrade и
  WebSocket frames; auth/rooms всё ещё doubles, не доказательство admission в Redis.
- test_signaling_integration.py: полное приложение, PostgreSQL и Redis через
  ASGI WS; без TCP, требует двух тестовых URL. Проверяет фактическую активацию,
  presence после отключения, чужой аккаунт и неизменность неизвестной Redis schema.

Ни один из этих уровней не заменяет последующие проверки heartbeat, гонок
переподключения, shutdown всего продукта или реальные сети/устройства.
